## Evidence-driven test corrections after the first attempt

1. `scripts/test-model-switch-ui.mjs`: a deterministic execution of the actual `useDraft` hook confirmed that filling before the renderer selects B writes the text to A; B's arrival then restores its empty draft and disables Send. Wait for the actual target ID/title/sidebar/runtime/pending state before filling. Preserve ordinary enabled-button, model and request-count assertions. This establishes a real test race, but the first CI failure lacked a snapshot, so its exact cause is not claimed as conclusively identified.
2. The same script's asynchronous `waitForFunction` predicates could return a truthy Promise before their condition was evaluated in Playwright 1.64. They now return synchronous booleans from public state events. No fixed sleep, retry, forced click or repeated bootstrap polling is used. Failures now save JSON and screenshots under `output/playwright/model-switch-ui-<platform>/`, before cleanup, while rethrowing the original error.
3. `tests/session-activity.test.ts`: injected assertion failure proved that fixture disposal could await an unreleased test gate. `finally` now releases it before waiting for completion/disposal; entry is bounded at 5 seconds. The same injected assertion now fails with exit 1 in 0.67 s instead of hanging; a missing-entry injection fails and cleans up in 5.47 s. Separately, the completed Windows log identified the actual `EBUSY` cleanup failure in the test that creates an additional `SessionAgents`: its disposal hook was registered after the fixture's directory removal. That test now disposes those processes in its body's `finally`, before the fixture can remove their working directory. No directory-removal retry or delay is added. A deterministic directory-removal boundary reproduced the original `EBUSY` and hanging process; after the fix it observes both owners disposed before removal, including an injected assertion failure (exit 1 in 0.73 s).
4. `npm test` has a 120-second Node test timeout, and the workflow's unit-test step has a 3-minute ceiling. Timeouts fail the check and keep logs; they are not a root-cause fix. The separate step ceiling covers referenced-handle leaks that survive already-passed test functions. Last successful baseline Windows suite took 37.3 s, with its longest individual test 9.0 s.
