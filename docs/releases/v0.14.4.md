# Pi Desktop v0.14.4

本版修复新建对话后，输入框已有模型信息却仍提示“选择一个模型”的问题。

## 本版变化

- 统一输入框与环境指引使用的会话模型状态。已读取可用模型时，新对话无需重复配置模型。
- 新对话使用当前会话或桌面保存的模型偏好；未保存偏好时显示“Pi 默认模型”，避免误显示上一条对话的模型和推理深度。连接后显示 Pi 实际使用的模型。
- 首次使用、未找到 Pi，以及连接后确实未选中模型的情况仍保留相应配置指引。
- 增加会话模型显示回归测试，覆盖新建按钮、Windows/Linux 的 Ctrl+N 和 macOS 的 ⌘N，以及已有会话的模型选择。

## 下载与更新

- Windows x64：推荐使用 `Pi-Desktop-0.14.4-win-x64-setup.exe`；便携版为 `Pi-Desktop-0.14.4-win-x64.exe`。
- macOS：Apple 芯片选择 `Pi-Desktop-0.14.4-mac-arm64.dmg` / `.zip`，Intel 芯片选择 `Pi-Desktop-0.14.4-mac-x64.dmg` / `.zip`。
- Linux x64：选择 `Pi-Desktop-0.14.4-linux-x86_64.AppImage` 或 `Pi-Desktop-0.14.4-linux-amd64.deb`。
- Windows 安装版和 Linux AppImage 支持应用内更新；其他安装方式请从发布页下载。`SHA256SUMS.txt` 提供发布资产的 SHA-256 校验值。

仍需本机安装 Node.js 22.19 或更高版本及 Pi Coding Agent。完整功能回归使用 Pi 1.1.0；本版不会自动安装或升级 Pi。macOS 安装包仍未签名、公证，首次打开方式见 README。

## 验证边界与已知问题

- 本次修复已在 Apple 芯片 Mac 上完成构建、单元测试、Pi 集成测试、新建对话及模型切换界面回归，并在实际 Pi 1.3.0 配置下检查新对话显示。Pi 1.3.0 的完整功能兼容性尚未验证。
- 三平台原生菜单与系统主题的实机人工验收仍待完成；[#1](https://github.com/yeyuProject/pi-desktop-gui/issues/1) 保持开启。
- 历史会话切换性能尖峰仍在调查，200 毫秒目标继续采样，超限暂作可见告警。本版不承诺所有切换低于 200 毫秒。
