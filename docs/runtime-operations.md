# 运行中的操作规则

每个桌面会话持有独立 Pi 进程、操作队列和运行状态。页面选择不更换后台进程。个人配置文件、项目目录和 Pi 原生终端仍可能共享，需要按实际对象检查冲突。

| 操作                                           | 影响对象                           | 生效时间                       | 入口规则                                                                                              |
| ---------------------------------------------- | ---------------------------------- | ------------------------------ | ----------------------------------------------------------------------------------------------------- |
| 切换、新建会话；草稿、附件                     | 指定会话及其草稿                   | 立即                           | 运行时保留；草稿写入继续受存储保护                                                                    |
| 模型、推理级别                                 | 指定会话下一次新用户任务           | 本轮结束后的新发送前交给 Pi    | 可选择；待生效时展示本轮值和下次值                                                                    |
| 立即补充、完成后执行队列                       | 当前会话的当前任务                 | 按 Pi 队列规则处理             | 模型与推理沿用当前任务，不能因为发起了下一次模型请求就应用新选择                                      |
| 审批模式、撤回授权                             | 该会话后续工具调用                 | 设置成功后立即                 | 已开始的命令继续，已有审批由用户处理                                                                  |
| 重试、自动压缩开关和队列发送方式               | 当前会话后续步骤                   | 立即更新 Pi 设置               | 不取消已开始步骤；取消重试另设入口。Pi RPC 只能通过停止当前操作取消压缩，按钮明确写明会停止压缩及任务 |
| MCP、Skills、扩展和提示词配置                  | 相同个人配置目录或相同项目工作目录 | 随时保存；各相关会话安全后加载 | 编辑保存可用，显示待加载；没有 Pi 时可先保存，连接后加载                                              |
| 资源包安装、更新、移除                         | 实际共用包文件的进程与终端         | 相关进程空闲，终端交接结束后   | 保留入口并解释需停止相关任务；配置文件仍可编辑                                                        |
| Pi、Node、配置目录路径                         | 下一次启动的对应进程               | 下次进程启动                   | 保存不关闭现有进程；已有连接不因新路径未就绪而被禁用                                                  |
| 历史、会话树、资源、文件、差异、用量           | 所查看会话或目录                   | 立即读取                       | 不要求任务空闲；原生终端独占的会话不能通过读取入口暗中启动第二个 Pi                                   |
| 导出、分享                                     | 点击时已产生的内容                 | 保存对话框前固定快照           | 可在运行中使用；含已收到的流式文字、工具输出。分享使用独立临时文件，上传仍需用户确认                  |
| 从历史分支、克隆                               | 新建独立会话和历史文件             | 立即创建                       | 原进程、任务和审批继续；没有历史时隐藏入口                                                            |
| 编辑历史、重新生成、切换当前历史分支、手动压缩 | 目标会话当前使用的上下文           | 目标会话空闲后                 | 临时冲突保留入口和原因，其他会话继续                                                                  |
| 撤销文件、生成项目规则                         | 真实目录及已知写入目标             | 相关任务停止后                 | 先预留修改范围，再检查任务；共享、嵌套或链接目录均检查，其他目录不阻塞                                |
| 停止、强制结束、取消重试、清空队列             | 明确指定的会话                     | 立即请求                       | 无对象时隐藏停止/取消/恢复；清空队列只恢复该会话草稿                                                  |
| 停止所有会话                                   | 所有会话                           | 用户明确确认后                 | 侧栏独立入口；不复用当前会话停止按钮                                                                  |

应用退出和安装应用更新需要检查全部会话。存储只读、项目未信任、未确认的残留进程、文件版本变化和 Git 分支变化继续保留对应保护；它们不转化为整应用“正在运行”限制。独立对话隐藏项目文件和变更入口，保留工具输出。

## Pi 原生行为与实现

以本地安装的 Pi 1.1.0 源码核对：`AgentSession._installAgentRequestProjection` 每次模型请求读取当前模型/推理；`setModel`、`setThinkingLevel` 立即改变这份状态。因此桌面保存待选值，在新用户任务前才调用原生接口。推理级别能力和调整使用 Pi 同一组 `getSupportedThinkingLevels`、`clampThinkingLevel` 函数。

`setAutoRetryEnabled`、`setAutoCompactionEnabled` 更新后续步骤使用的原生设置，不取消当前步骤。配置保存采用与原生 `SettingsManager` 相同的 `proper-lockfile` 锁，在锁内做版本校验和备份，避免多个进程丢失修改。

分支使用独立 `SessionManager` 的 `createBranchedSession`，不在源进程执行会替换活动会话的 `fork`/`clone`。目录修改与进程启动的保护位于 `SessionAgents`，会话内的任务、设置、读取和安全加载由 `AgentService` 管理。

## 验证入口

- `npm test`：会话状态隔离、操作顺序、终端交接、目录冲突、配置锁、检查点和存储回归。
- `npm run test:concurrency`：真实 Pi + 本机模型接口，验证双会话、审批归属、设置实际生效时间、安全加载、历史分支、导出快照及界面重载。
- `npm run test:pi-settings-ui`：真实 React 控件验证运行中保存、待加载说明、旧读取结果隔离、配置失败和存储保护。
