# v0.10.0 会话切换与模型错误验收

日期：2026-10-15。范围：PRD S1、S2。Pi 回归基准为 1.1.0，使用隔离的本地模型接口；未改变支持版本范围。

## 行为与模块边界

- 原流程原生切换后仍重启 Pi。现在 `ensureConnected` 决定复用或重启，`installRpcHandlers` 安装进程监听，`rebindSession` 统一恢复历史、工具、模型、推理级别、能力与审批。行为保持的提取先单独提交为 `01b4927`，之后再实现功能。
- 同目录使用原生 `switch_session/new_session`，跨目录重新启动。复用失败恢复为重启；扩展明确取消则保留原会话。运行环境变化仍先断开。
- 适配扩展协议升为 2，增加公开 `session_start` 的桌面标记，划分旧钩子与目标启动事件。该标记还与审批临时授权清空保持同一生命周期。
- `shared/errors.ts` 集中分类和脱敏，`ModelErrorCard.tsx` 集中展示；进程和存储错误不使用模型分类。计数按会话和错误类别保存，只有最终失败才计数，成功后清零。
- 错误详情在显示、复制和诊断前脱敏；读取历史时仅处理错误字段，Pi 原始 JSONL 保持不变。

## 跨目录对比

`scripts/test-session-context.ts` 创建两个项目，在 B 的项目扩展中按 `process.cwd()` 注册命令：

| 检查 | 冷启动 B | 从 A 原生切换到 B |
| --- | --- | --- |
| 信任项目时加载 B 扩展 | 是 | 是 |
| 扩展读到的进程目录 | B，注册 `cwd-project-b` | A，注册 `cwd-project` |
| 项目自动压缩设置 | 与原生切换一致 | 与冷启动一致 |
| 禁止信任项目时 B 扩展 | 未加载 | 未加载 |

原生跨目录切换无法保证扩展行为与冷启动一致，因此产品明确限制为同目录复用。没有通过修改 Pi、临时替换目录或猜测字段绕过这一差异。

## 证据边界

- 200 毫秒指标只针对同工作目录内已存在的会话，不包括跨目录冷启动、首次连接或等待用户回答扩展确认框。
- 性能计时由真实侧栏点击开始，到目标消息更新后的绘制帧结束；后端耗时另记，不能替代界面指标。应单独运行性能用例，避免其他本地测试争用 CPU。
- 这些回归覆盖已验证 Pi 的公开协议和测试扩展，不声称任意第三方扩展都兼容，也不放宽 Pi 主/次版本准入。
