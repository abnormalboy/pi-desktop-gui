## v0.1.1 界面优化（2026-10-11）

参考 [Apple HIG 设计原则](https://developer.apple.com/design/human-interface-guidelines/design-principles/) 中的简洁、熟悉、灵活和用户掌控，沿用 Windows 桌面操作习惯调整界面：

- 对话成为主工作区，默认收起右侧检查面板；标题、项目和分支合并为紧凑工具栏，完整目录保留为悬停提示。
- 统一中性色表面、可读的次要文字、字号、控件尺寸与圆角；绿色只用于主要操作和选择状态。深色主题同步调整。
- 阅读区和输入框使用一致的内容宽度；缩减欢迎页文案和装饰，工具过程以紧凑行呈现，展开后显示详细输入与输出。
- 模型选择靠近任务输入，输入框自动增高；运行状态和耗时位于输入区下方。字体设置同步缩放正文与功能标签。
- `Ctrl+B` 切换侧栏，并在重新打开应用后保留选择。工作区宽度不足时检查面板使用抽屉，锁定背景交互、管理 Tab 焦点，并支持 Esc 返回。
- 从抽屉引用文件或继续提问时，自动收起抽屉并聚焦输入框。Git 差异阅读区从首个 hunk 开始，省去重复文件头；正文中的加减行保持原样。

## 实现结构

| 目录 | 职责 |
| --- | --- |
| `src/` | React 界面、Markdown、工具卡、文件与差异、设置及扩展对话框 |
| `electron/main.ts` | Electron 生命周期、原生文件选择、来源校验后的 IPC 与系统集成 |
| `electron/preload.ts` | 仅暴露 `invoke` / `onEvent` 的受限桥接 |
| `electron/agent.ts` | 会话服务、RPC 事件、稳定结束、排队、停止、扩展交互 |
| `electron/rpc.ts` | 严格 LF JSONL、分块 UTF-8、请求 ID、超时、stdout 排空、进程树结束 |
| `electron/workspace.ts` | 项目内预览与引用、Git 工作区、运行前文本基线 |
| `electron/store.ts` | 原子索引、草稿、异常状态恢复、Pi JSONL 活跃分支读取 |
| `tests/`、`scripts/` | 协议夹具、真实 Pi 本地接口验收、桌面 UI 验收与构建 |

界面不持有 Node.js API；主进程不把提供商 headers 等敏感模型字段发送到界面。Pi 子进程沿用用户配置。停止顺序为冻结新发送、清空队列并恢复文本、取消扩展请求、abort、查询状态确认。`prompt` 响应和 `agent_end` 都不会直接标记任务完成。

## 使用边界与剩余事项

- v0.1 使用欢迎页和设置完成初始配置，尚未实现 PRD 线框中的独立三页向导；登录在 Pi 终端完成。
- 支持项目/会话索引与导入；不提供 Git 写操作、编辑器内编辑、任务回滚、并发智能体、后台托盘任务和自动更新。
- 当前文件树按需读取；会话首次显示最近 80 条，可逐批加载历史。尚未完成 PRD 的 1,000 消息/50,000 行日志及 30 次 p95 性能基准，不能宣称达到该性能目标。
- Git 运行基线只覆盖限额内文本，不包含二进制和超大文件；未包含文件会列出。它记录最近一次在该项目开始的任务，而不是文件变化归因系统。
- 工具日志显示与导出有明确上限；原始 Pi 会话保留在 JSONL。文件被其他程序改动后，差异列表轮询刷新，已打开的差异可以点击刷新重新读取。
- 本机 Windows 已运行测试；干净 Windows 虚拟机、不同企业环境、正式代码签名、安装/升级/卸载矩阵和真实商业模型提供商验收尚未进行。这不是 PRD M3 正式发行验收完成的声明。

## 本次发现并修复的问题

- Git for Windows 安装在非系统盘时，Pi 原有的 Bash 搜索未找到可执行文件；启动环境现在优先包含检测到的 Git Bash。
- Git 跟踪但已删除的文件，以及新增的空文件，最初未出现在运行差异中；比较现在同时考虑文件存在性与内容。
- 扩展命令返回 `handled` 而没有 agent loop 时，界面最初可能停留在运行态；现在查询 Pi 实际状态后回到就绪。
- 提供商模型记录可能包含请求 headers；传到 renderer 的模型现在只保留展示字段。
- 小窗口自动收起文件面板；工具调用专用的空 assistant 消息不再生成多余对话气泡。

协议适配升级时应重新运行三层验证。原始产品规划仍保留在 [PRD](PRD.md)，以便逐项追踪后续发布目标。
