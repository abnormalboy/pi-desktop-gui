## 关键回归与独立审阅

1. Pi 会等待用户消息和工具扩展事件：普通消息先准备检查点，排队消息在前一轮结束后捕获，并在自己的模型请求前完成。保存失败阻止模型请求，草稿保持原样。
2. 12 个写入工具并行开始/结束，检查点状态更新与落盘统一串行；没有同名临时文件竞争。重开 Workspace 后全部路径仍被正确记录；失败一次也不阻塞后续队列。
3. 手动编辑与无法确认来源的内容默认不恢复；确认期间文件变化会拒绝全部恢复。提交不使检查点失效，快速切出分支再切回也会失效。
4. 私有索引禁用项目文本转换和过滤，验证 LF/CRLF、二进制、重启以及目录被替换为 junction 的情况。POSIX 权限专项保留在跨平台 CI 中执行。
5. 后台 A 会话结束后，在 B 项目不能直接重跑 A 的命令。回到历史消息时清空旧分支的实时工具列表，避免旧工具继续显示为当前工作。
6. 外部编辑草稿包含长文本片段，导入时检查草稿是否已变化；空会话清理在确认后重新检查草稿、附件、图片、片段和活动连接。

独立审阅发现的两个 P1（跨项目重跑、并行检查点写入）均已修复。补审验证了串行队列不会等待自身，失败后仍可继续，没有剩余确认的 P1/P2。

## 性能与限制

| 测量 | 结果 |
| --- | --- |
| 500 条消息、100 个工具、60 次流式更新 | 中位 14.6 ms，P90 15.4 ms；同机 v0.8 中位 15.0 ms，满足增加不超过 2 ms 的目标 |
| 500 条消息搜索和高亮切换 | 最终完整界面回归中位 2.8 ms，P95 5.4 ms；未命中的历史消息 DOM 更新为 0 |
| 一万文件项目首次检查点 | 3572.5 ms，包含首次安全扫描和私有索引建立 |
| 一万文件后续 19 轮检查点 | 中位 597.2 ms，最快 514.8 ms；**未达到每轮 500 ms 的原定指标** |
| 20 轮快照容量 | 总占用 7,475,830 字节，实际修改 6,641,032 字节，比值 1.126；新增占用比值 0.776，满足本次数据集的 2 倍目标 |

性能脚本是 `scripts/perf-ui.mjs` 与 `scripts/test-workspace-v014-performance.ts`。指标取自本机 Windows，不能代替其他文件系统或更大项目的性能证明。为保证路径和原始内容安全，首次扫描没有跳过文件检查。

本地用量按会话最后活动日期选择整份会话后聚合，包含历史分支和压缩记录，缺失费用显示未知；它不提供服务商逐日账单。文件撤销不会撤销数据库、网络请求或安装等副作用。未验证 Pi 版本允许尝试，协议不符合时仍明确失败，不猜测新旧字段。

结构自评 **7/10**：新增职责已有独立模块、多个入口共用纯逻辑，稳定消息对象和增量事件仍保留；主进程 IPC 和 Agent 生命周期文件依然较大，本次没有为缩短文件而再引入通用框架。
